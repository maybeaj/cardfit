| Q04 | "186,000원 더 유리해요"의 비교 대상(기존 카드 대비인지)이 명확히 전달되는가? | 비교 기준 명확화 및 안내 툴팁 추가 |

| Q06 | [계산 근거] 팝업의 전월실적, 차등 구간 등 전문 용어가 일반 유저에게 너무 어렵지 않은가? | 난이도 조절 및 쉬운 용어 가이드 |
| Q07 | 기존 카드 해지가 포함될 경우 연회비 환급이나 포인트 소멸에 대한 안내가 제공되는가? | 카드 교체 시 이탈/불안감 방지 |
| Q08 | 카드사 아웃링크 이동 후 다시 앱으로 돌아왔을 때, 입력했던 데이터가 유지되는가? | 세션 유지 및 복귀 유저 경험 |
| Q09 | 카드사 자체 신규 발급 이벤트와 서비스 계산 로직 간 오해가 생기지 않는가? | 혜택 중복/혼선 방지 팝업 |
| Q10 | 계획했던 대형 지출이 변경되었을 때 쉽게 기존 계획을 수정하고 재계산할 수 있는가? | 재설계 동선 및 계획 관리 유연성 |

| Q15 | 카드사 제휴 수익(CPA)을 붙일 때 특정 카드사 편향 없이 추천 알고리즘의 중립성을 유지할 수 있는가? | 데이터 추천 객관성 및 제휴 정산 구조 |

| Q17 | 계산 오차로 인해 예상 혜택을 받지 못했다는 고객 항의 시 면책 및 법적 리스크를 어떻게 관리할 것인가? | 약관 및 하단 면책 문구(Disclaimer) 정립 |
| Q18 | "언제 결제해야 하나요?", "링크 연결이 안 돼요" 같은 반복 문의에 대한 CS 대응 가이드가 있는가? | CS FAQ 및 대응 프로세스 구축 |
| Q19 | 특정 시점 마케팅이나 이벤트로 트래픽이 몰릴 때 계산 서버 API의 과부하를 견딜 수 있는가? | 트래픽 제어 및 인프라 과부하 대비 |
| Q20 | 사용자가 입력한 미래 지출 계획 데이터를 어디까지 저장하고 언제 보안 파기할 것인가? | 개인정보 보호 및 데이터 보안 정책 |
