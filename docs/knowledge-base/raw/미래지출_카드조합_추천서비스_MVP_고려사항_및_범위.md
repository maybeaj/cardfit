# 1. Summary

이 서비스는 사용자가 입력한 미래 소비의 **카테고리·금액·시점**을 바탕으로 보유카드와 신규카드 후보의 실적조건·혜택한도·연회비를 계산하여, 카드별 역할과 소비 배분안을 추천하는 서비스다.

1차 MVP의 목표는 모든 카드와 혜택을 완벽하게 계산하는 것이 아니다.

> **제한된 카드 후보군 안에서 미래 소비를 카드별로 재배분하고, 왜 해당 조합이 유리한지 재현 가능한 계산으로 설명하는 것**

현재 확정된 범위는 다음과 같다.

| 구분 | 확정 내용 |
| --- | --- |
| 1차 MVP | 카테고리별 예상지출을 기준으로 카드사 기본혜택과 카드조합 계산 |
| 교통비 | 1차 MVP 카테고리에 포함 |
| K-패스 카드 | 신용·체크카드 상품 후보로 포함 가능 |
| 정부·지자체 환급 | 1차 계산에서 제외하고 별도 정책혜택으로 표시 |
| 신규카드 | 최대 1장을 추가하는 시나리오까지 비교 |
| 2차 MVP | 구체 사용처·브랜드·프로모션을 반영한 구매별 결제설계 |
| 마이데이터 | MVP에서는 연동하지 않고 사용자 직접입력 방식 사용 |

# 2. 서비스 계산 구조

## 2.1 입력

- 사용자의 현재 보유카드
- 미래 소비의 카테고리·금액·시점
- 일회성·반복지출 여부
- 신규카드 수·연회비·카드 관리 부담 등 사용자 제약

## 2.2 계산

- 카드별 전월실적 달성 가능성
- 할인·적립 대상과 혜택한도
- 카드별 소비 배분
- 기존 카드에서 소비를 이동할 때 사라지는 혜택
- 연회비를 차감한 예상 순혜택

## 2.3 출력

- 보유카드만 사용하는 안
- 신규카드 1장을 추가하는 안
- 카드별 역할과 배분금액
- 예상 카드사 혜택과 계산 근거
- 적용되지 않은 조건과 불확실성

## 2.4 기본 목적함수

> **예상 순혜택 = 카드사 할인·적립 − 연회비 − 실적 충족비용 − 기존 카드에서 잃는 혜택 − 카드 관리비용**

정책형 카드의 정부·지자체 환급은 1차 MVP의 목적함수에 포함하지 않는다.

### 1차 MVP 처리 원칙

1차 MVP에서는 교통비를 일반 소비 카테고리로 포함하고 **카드사가 제공하는 자체 혜택만 계산**한다.

K-패스·모두의 카드 등 정부·지자체 환급은 계산하지 않고 다음과 같이 표시한다.

> 예상 카드사 혜택: 월 5,000원  
> K-패스·모두의 카드 등 정부·지자체 정책환급은 본 계산에 포함되지 않았습니다.

정책환급을 제외한 상태에서 K-패스 카드와 일반 교통카드를 비교할 경우 총혜택 순위가 달라질 수 있다. 따라서 결과의 명칭은 `총 교통비 절감액`이 아니라 **카드사 자체 혜택 기준 비교**로 제한한다.

# 4. 1차 MVP 범위

## 4.1 반드시 포함

- 사용자 직접입력
- 현재 보유카드
- 카테고리별 예상금액·시점
- 일회성·반복지출 구분
- 교통비 카테고리
- 검증 가능한 제한된 카드 후보군
- 전월실적과 실적구간
- 주요 실적 제외 항목
- 할인·적립률
- 월별 혜택한도
- 연회비
- 카드 간 소비 재배분
- 신규카드 최대 1장
- 전체 카드 수 제한
- 보유카드안과 신규카드 추가안 비교
- 예상 순혜택과 계산 근거
- 공식 출처와 기준일

## 4.2 단순화

- 카드 후보군은 공식 약관을 검증할 수 있는 소수로 제한
- 할부는 사용자 제약으로 입력하되 사용처별 무이자행사는 계산하지 않음
- 포인트는 하나의 고정된 현금가치 기준으로 환산
- 교통은 `버스·지하철 / 택시 / 철도` 정도로만 구분
- 정부·지자체 환급은 계산하지 않고 별도 표시
- 일시적 프로모션보다 카드 기본혜택 중심으로 계산
- 카드 관리 부담은 정교한 금액이 아니라 사용자 선호·카드 수 제한으로 반영

## 4.3 제외

- 구체 백화점·매장·브랜드
- 실시간 프로모션
- 정부·지자체 환급액 계산
- 마이데이터 연동
- 실시간 카드혜택 갱신
- 자동 카드발급
- 자동 결제수단 전환
- 정책 변경 알림
- 구매건별 정밀 분할결제

# 5. Guardrail

## G-01. 불필요한 신규카드 추천 방지

자연적으로 발생할 소비만으로 전월실적을 달성할 수 없는 카드는 원칙적으로 추천하지 않는다.

## G-02. 총혜택 과장 방지

정부·지자체 정책환급, 사용처 프로모션 등 계산하지 않은 혜택이 있으면 `총혜택`이라는 표현을 사용하지 않는다.

## G-03. 데이터 최신성

카드혜택의 공식 출처와 확인일을 함께 제공하고, 기준일이 오래됐으면 추천 정확도 경고를 표시한다.

## G-04. 계산과 설명 분리

할인·적립금액은 규칙 엔진이 계산하고, AI는 계산 결과와 근거를 사용자 언어로 설명한다.

## G-05. 카드 수 통제

명목상 혜택이 증가하더라도 카드 수와 관리 부담이 사용자의 제약을 초과하면 추천하지 않는다.

## G-06. 추천 불가 상태

약관정보가 누락됐거나 혜택 적용 여부를 판단할 수 없는 경우 임의로 추정하지 않고 `확인 필요`로 분류한다.

# 7. 확인된 근거와 남은 가설

## 확인된 사실

- 일부 마이데이터 기반 카드추천 서비스는 사용자의 과거 소비패턴을 기준으로 카드혜택을 비교한다.
- K-패스 신용·체크카드는 정부 정책환급과 별도로 카드사 자체 교통혜택과 전월실적 조건을 가질 수 있다.
- 카드에 따라 교통비의 실적 포함 여부, 할인한도, 대상 교통수단이 다르다.
- 여러 신용카드를 보유하는 행위 자체가 NICE 개인신용평점의 직접 하락요인은 아니지만, 연회비·실적 분산·관리 부담은 실제 경제적 비용이 될 수 있다.

## 검증이 필요한 가설

- 미래 소비를 입력하면 과거 소비기반 추천보다 의사결정 가치가 커진다.
- 사용자는 카드 한 장보다 카드조합과 소비 배분안을 원한다.
- 카드 수와 관리 부담을 반영한 균형안이 최대혜택안보다 더 많이 선택된다.
- 교통비를 포함하면 정책형 신용카드까지 후보군이 넓어져 추천가치가 높아진다.
- 사용자는 정부환급이 제외된 카드사 혜택 비교도 유용하다고 평가한다.

# Insight

이 서비스에서 복잡성이 발생하는 이유는 카드의 수가 많기 때문만이 아니다. 혜택률·전월실적·혜택한도·제외조건과 카드 간 소비 이동의 기회비용이 서로 영향을 주기 때문이다.

따라서 1차 MVP는 모든 변수를 완벽히 다루기보다 다음 핵심 능력을 입증해야 한다.

> **제한된 카드 후보군에서 미래 소비를 재배분하고, 실적 충돌과 카드 수 제한을 반영해 실행 가능한 카드조합을 근거와 함께 제시한다.**

이 핵심 능력이 검증된 이후에 사용처·프로모션·정책환급을 순차적으로 추가해야 한다.
