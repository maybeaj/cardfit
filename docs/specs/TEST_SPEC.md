## 1. 검증 원칙

계산 정확성은 정답셋 비교로, UX 경계는 사용자 흐름으로 검증한다. 실연동·사용자 조사·선택률은 이 프로토타입의 테스트 통과 주장에 포함하지 않는다.

## 3. 계산 단위 테스트

- 임계 경계: `49,999/50,000원`, Gross의 `14.99/15%`를 각각 검증한다.
- 같은 입력을 3회 실행해 결과 객체의 깊은 동등성을 확인한다.
- 동률 후보가 정해진 순서로 선택되는지 확인한다.
- 배분 합과 입력 총액의 차이가 1원 이하인지 확인한다.
- 연회비를 안분하지 않으며 7개월 이후 발급 고지가 생성되는지 확인한다.
- 출처 없는 `unmodeled_bound`가 결과에서 제외되는지 확인한다.

## 4. E2E·반응형

- 실행 명령: `npm test`(Vitest) · `npm run test:e2e`(Playwright) · `npm run build`.
- Playwright는 `mobile`(402×874)과 `desktop`(1440×900) 두 프로젝트로 같은 시나리오를 돌린다.
- `/`에서 시작해 `/app/confirm`까지 랜딩→앱 데모를 한 번에 완주한다.
- `change_case`는 기본 흐름으로, `maintain_case`는 단위 테스트에서 프로필을 주입해 검증한다 — 화면에 프로필 선택 UI를 만들지 않기 때문이다 (`T17`).
- 402×874와 1440×900에서 가로 스크롤 없이 핵심 CTA와 결론이 보인다.
- 외부 링크를 새 탭으로 연 뒤 돌아오면 입력과 확정 조합이 유지된다.
- 금지어와 Mock 오인 문구는 `src/content/copy.ts`의 `BANNED_TERMS`를 기준으로 단위 테스트와 E2E에서 함께 스캔한다.

## 5. 미충족 항목 — 완료로 표시하지 않는다

`docs/tasks/FX-01.md`·`QA-01`·`QA-02`의 완료 조건 중 아직 만족하지 않은 것을 여기에 남긴다. 구현이 명세를 조용히 대체하지 않기 위한 목록이다.

| 항목 | 요구 출처 | 현재 상태 |
| --- | --- | --- |
| `42,000원` 판정 케이스 | `FX-01` 완료 조건 · `T-AC004` | **미구현.** Fixture가 2개(`186,000`·`31,000`)뿐이다. 이중 임계의 두 다리 중 **상대 조건(Gross×15%) 미달로 유지되는 케이스**가 없다 — 현재 두 Fixture는 모두 절대 조건(5만원)에서 걸린다 |
| `maintain_case` 모바일 E2E | `QA-02-02` | **미구현.** 단위 테스트로만 검증. 화면에 프로필 선택 UI가 없어(`T17`) E2E로 태우려면 `변경 조건`에서 `신규 발급 빼요`를 고르는 경로를 쓴다 |
| 아웃링크 복귀 후 세션 복원 E2E | `QA-02-03` · `FE-03-07` | **미구현.** `sessionStorage` 어댑터는 구현했으나 새 탭 복귀 시나리오 테스트가 없다 |
| 가로 스크롤 0건 검증 | `DS-01` 완료 조건 | **미구현.** 두 폭에서 렌더는 확인했지만 `scrollWidth` 검사가 없다 |
| 비밀키·개인정보 정적 스캔 | `QA-01-04` · `NFR-002` | **미구현.** 현재 환경변수·비밀값이 0개라 위반은 없지만 검사 명령이 없다 |

## 6. 완료 판정

P0 테스트 전부 통과, `npm run build` 성공, 배포 URL에서 콘솔 오류 0건, 비밀키·개인정보 스캔 0건이어야 프로토타입을 완료로 표시한다. 사용성·선택률은 관찰하지 않았다고 별도로 고지한다.
