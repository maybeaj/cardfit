# CardFit 마이데이터 이용 동의·약관 법적 검토 메모

- 검토일: 2026-09-02
- 대상: CardFit 프로토타입의 마이데이터 이용 동의 바텀시트와 향후 실서비스 전환 기준
- 상태: 프로토타입 UX 반영 완료 · 실서비스 출시 전 법무·준법 최종 검토 필요
- 관련 문서: [`PRD.md`](../PRD.md), [`SRS.md`](../SRS.md), [`ux/README.md`](../ux/README.md), [`adr/ADR-001-mock-first.md`](../adr/ADR-001-mock-first.md)

> 이 문서는 법률 자문서가 아니다. 공식 법령·금융위원회 안내를 바탕으로 제품 요구사항과 프로토타입의 누락 위험을 정리한 개발용 검토 메모다. 실제 서비스는 사업자 지위, 제휴·전송기관, 개인정보처리방침, 동의서 전문, 보유기간, 철회·파기 절차를 확정한 뒤 법무·준법 승인을 받아야 한다.

## 1. 결론 요약

1. 프로토타입에는 `마이데이터 이용 동의하기` 바텀시트를 두고 이용 목적·범위, 필수 동의 항목, 철회 가능성, 프로토타입용 예시 데이터 사용 사실을 표시한다.
2. 실제 마이데이터 연동·인증·전송은 v0.1 범위에 포함하지 않는다. 프로토타입의 체크박스는 실제 법적 동의를 수집하지 않는 UI 검증용 표시다.
3. `최근 12개월 결제 내역`은 CardFit의 계산 대상 데이터 범위다. 이것을 동의 유효기간 또는 법정 파기기간인 것처럼 표현하지 않는다.
4. “한 번 동의하면 12개월 동안 유지된다”는 문구는 법적 일반 원칙으로 확정하지 않는다. 마이데이터 2.0 안내상 가입 유효기간은 1년 단위로 최대 5년까지 선택할 수 있으며, 장기 미접속에 따른 정기 전송 중단·정보 삭제 기준이 별도로 존재한다.
5. 실서비스에서는 제공받는 자, 이용 목적, 정보 항목, 이용·보유기간, 동의 거부권과 불이익, 정기·비정기 전송 여부, 철회·삭제 방법을 실제 사업 구조에 맞춰 전문으로 제공해야 한다.

### 프로토타입에서 사용하는 체크박스

현재 프로토타입은 다음 세 행을 모두 `[필수]`로 표시한다.

- 개인정보 수집·이용
- 개인신용정보 전송요구
- 제3자 제공·처리위탁

이는 사용자가 동의 구조를 이해하는지 검증하기 위한 대표 UI다. 실서비스에서는 세 항목을 항상 별도 필수 동의로 고정할 수 없으며, 실제 사업자 지위와 정보 흐름에 따라 법무 검토 후 필수·선택·고지 항목을 다시 분류해야 한다. 특히 처리위탁과 제3자 제공은 수령 주체와 처리 목적이 달라질 수 있으므로 하나의 문구로 합치지 않는다.

## 4. 12개월 표현 사용 규칙

다음 표현은 서로 구분한다.

- 허용: `최근 12개월 결제 내역을 카드 조합 계산에 사용합니다.`
- 허용: `가입 유효기간은 실제 동의 화면에서 선택한 기간을 기준으로 합니다.`
- 허용: `동의 철회 및 데이터 삭제 방법은 약관과 개인정보처리방침에서 확인할 수 있습니다.`
- 금지: `마이데이터는 법적으로 12개월마다 무조건 파기됩니다.`
- 금지: `한 번 동의하면 모든 데이터가 12개월 동안 유지됩니다.`

프로토타입의 `1년 · 언제든지 철회할 수 있어요` 표시는 실제 법정 기간을 확정하는 문장이 아니라 화면 흐름을 위한 예시다. 실서비스 전환 시에는 실제 가입 유효기간 선택값과 철회·파기 결과를 서버 상태 및 감사 로그에 남겨야 한다.

## 4-1. “받은 혜택” 데이터 표현 검토

마이데이터로 보유 카드와 카드 결제·이용 내역을 받을 수 있다는 전제만으로 카드사가 실제로 확정한 할인·적립액까지 항상 직접 받을 수 있다고 단정해서는 안 된다. 실제 제공 항목은 업권·정보전송자·서비스 등록 범위에 따라 달라지며, 카드별 혜택 규칙과 적용 제외 조건도 별도로 관리해야 한다.

따라서 CardFit의 현재 확인 화면은 다음처럼 구분한다.

| 화면 표현 | 의미 | 사용 조건 |
| --- | --- | --- |
| 최근 12개월 받은 혜택 | 사용자가 이해하기 쉬운 요약 표현 | 하단에 `결제내역과 카드 혜택 기준을 대조한 계산값`을 함께 표시한다 |
| 카드사가 확정한 할인·적립액 | 청구서·리워드 원장 등 카드사가 직접 확정한 값 | 해당 데이터 항목을 실제로 제공받고 검증한 경우에만 사용한다 |
| 예상 혜택 | 미래 지출 계획을 적용한 계산 결과 | 현재 상태 화면의 받은 혜택과 섞지 않고 결과 화면에서만 사용한다 |

프로토타입은 첫 번째 표현을 사용하되 예시 계산값임을 명시한다. 실서비스에서 카드사가 확정한 혜택액을 제공하지 않는다면 `받은 혜택`을 `결제내역 기반 혜택 계산값`으로 변경한다. 이는 마이데이터 표준 전송 항목과 각 정보전송자의 실제 제공 범위를 확인한 뒤 확정한다. [온마이데이터 서비스·전송항목 조회 안내](https://www.onmydata.go.kr/mbr/intro/menu-guide-dtl), [온마이데이터 개발시험지원센터 API 안내](https://www.onmydata.go.kr/developers/guide/apiGuideList/SU)
