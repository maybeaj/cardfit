## 결정 이력

### T1 — 진입 구조 · RESOLVED

**decision:** 단일 선형 3라우트(`진단 → 입력 → 결과`) + 결과→입력 수정 루프 1개. 새 진입점·분기를 추가하지 않는다.

**근거:** 뱅크샐러드의 2경로(신규 탐색 / 보유 관리)는 상시 카드 관리 서비스의 구조다(경쟁사 PDF p2·p10 *"매월 반복되는 관리 루프"*). CardFit은 이벤트 트리거 기반 1회 계산이라 분기 근거가 없다. CardFit의 루프는 "월별 재방문"이 아니라 "입력이 틀렸을 때 되돌아가기"다.

**applied:**
- 설계문서: `docs/ux/README.md` 1절 — 라우트 다이어그램·표 교체, 종착점 선언 추가
- 하네스: `CLAUDE.md` **신설** (Rules 계층) — "새 진입점·탭·분기 추가 금지" 제약 명문화 + 계산·표기·데이터 제약 승계
- 원장: 이 파일

### T2 — 결과 화면의 주인공 · RESOLVED

**decision:** 결론 배너(좁게) + 배분표 본문(넓게). 주인공은 결제 배분표다. "유지" 결론일 때도 현재 조합 기준 배분표를 비우지 않는다.

**근거:** 경쟁사 PDF p11 — *"CardFit의 핵심 산출물은 카드 순위가 아니라 결제 계획이다. 사용자는 앞으로의 소비를 어떤 카드에 배분할지 확인해야 한다."* 게이팅(AC-004)은 CardFit의 정체성이라 뺄 수 없고 배분(FR-004)은 사용자가 들고 나가는 산출물이라, 배너와 본문으로 나누면 둘 다 산다.

**applied:**
- 설계문서: `docs/ux/README.md` 1-1절 신설(결과 화면 구조 다이어그램) · `docs/SRS.md` 4절 UI-005·UI-006 역할 재정의 + 별도 화면이 아님을 명시
- 하네스: `CLAUDE.md` UX 계약 2줄 추가 — 카드 순위 목록 금지, 유지 결론에서 배분표 비우기 금지
- 원장: 이 파일

### T3 — FR-006 초기값 제안의 위치 · RESOLVED

**decision:** 입력 화면의 초기 상태로 흡수한다. 별도 화면·단계를 두지 않으며, 사용자가 빈 폼을 마주하는 순간이 없어야 한다. 라우트 3개 유지.

**근거:** CJM 14절이 조민아형 온보딩 이탈의 개선안으로 지목한 것이 정확히 *"미래 지출 직접 입력을 곧바로 요구하지 않고 과거 패턴 기반 자동 초기값을 먼저 제시"*다. 앱 안에서 손댈 수 있는 이탈 지점은 이것 하나뿐이라(⑥ 실행은 권한 밖) 화면 상태로 흡수하는 쪽이 확실하다. 경쟁사는 입력 자체를 없애 회피했지만(PDF p4 *"사용자가 소비 금액을 직접 입력하지 않는다"*), CardFit은 미래 입력이 존재 이유라 그 길을 갈 수 없다.

**함께 정리한 문서 결함 2건:**
1. `SCOPE.md` 3절 Happy Path가 `F-01`부터 시작해 **Mock 로드와 F-11이 빠져 있었다.** `ux/README.md`가 이 절을 정본으로 지목하므로, 그대로 따르면 빈 입력 폼을 만들게 되는 상태였다.
2. `SCOPE.md` 5절이 F-11을 "보조 기능"으로 분류해 PRD·SRS의 Must와 충돌하는 것처럼 읽혔다 → "핵심/보조"가 시연 비중의 축임을 명시.

**applied:**
- 설계문서: `docs/SCOPE.md` 3절 Happy Path 전면 교체 + 정정 이력 · 5절 축 주의 행 · `docs/SRS.md` 2절 Happy Path 정정 + 라우트 주석 + FR-006 Rule 보강 · `docs/ux/README.md` 라우트 표 2행
- 하네스: `CLAUDE.md` — "입력 화면은 빈 폼으로 열리지 않는다"
- 원장: 이 파일

### T4 — 화면 경계 · RESOLVED

**decision:** 3라우트 + 섹션 접기. 요구사항 `UI-001~008` 8개를 전부 유지하되 화면은 3개로 접는다.

| 라우트 | 안에 들어가는 UI |
| --- | --- |
| 1 진단 | `UI-001` 현황 · `UI-003` 제약(인라인 블록) |
| 2 입력 | `UI-002` 입력 |
| 3 결과 | `UI-004` Loading 상태 · `UI-005` 결론 배너 · `UI-006` 배분표(본문) · `UI-007` 근거(펼침 패널) · `UI-008` 경계(하단 블록) |

**근거:** 8스테이지는 요구사항 단위지 라우트 단위가 아니다. `UI-004`(계산)는 애초에 화면이 아니라 Loading 상태로 정의돼 있고(SRS 7절), `UI-007`(근거)은 CJM ④단계가 신뢰 형성 지점이라 결과 옆에 붙어 있어야 이탈을 막는다. 경쟁사는 유의사항을 별도 화면으로 빼서 약관처럼 읽히는 구조다(PDF p7-8). 요구사항이 줄지 않으므로 SRS 4절의 "재설계하지 않는다" 원칙과 충돌하지 않는다.

**applied:**
- 설계문서: `docs/ux/README.md` 1절 라우트×UI 매핑 표 확정 · `docs/SRS.md` 4절 라우트 매핑 주석 추가
- 하네스: `CLAUDE.md` — "화면은 3라우트뿐, 근거를 별도 화면으로 빼지 않는다"
- 원장: 이 파일

### T5 — 진단 화면의 G2 경계 · RESOLVED

**decision:** 관찰된 사실만 노출한다. 금액 결론(절감액·예상혜택·추천 카드·과거 기준 손실)은 0건.

| 노출 가능 | 노출 금지 |
| --- | --- |
| 보유 카드 수·카드명 · 최근 6개월 소비 합계 · 실적 미달 카드 수 · 제약 현황 | 절감액 · 예상 혜택 · 추천 카드 · "얼마를 놓쳤습니다" · 근거 없는 티저 |

**근거:** `G2`·`AC-001`이 *"미래 입력 없이 산출된 결과는 결과로 취급하지 않는다"*이므로, 진단 화면에서 절감액을 띄우면 화면이 스스로 G2를 깨뜨린다. 경쟁사는 홈에서 *"최대혜택 1,223,085원 예상"*을 띄우지만(PDF p3) 그건 과거 1년 소비 기준이고, CardFit이 같은 걸 하면 PRD 3절 `P2`(*"기존 추천이 과거 소비만 본다"*)를 스스로 저지르게 된다. KSF③의 손실 가시화는 결과 화면의 차액 표시(`AC-006`)가 담당하며 거기서는 미래 입력을 거치므로 G2를 지킨다.

**applied:**
- 설계문서: `docs/ux/README.md` **1-0절 신설**(노출 가능/금지 표 + 화면 스케치) · `docs/SRS.md` 4절 UI-001 행 보강
- 하네스: `CLAUDE.md` — "진단 화면에는 금액 결론을 띄우지 않는다"
- 원장: 이 파일

### T6 — 신규카드 포함 범위 · RESOLVED

**decision:** 카드별 상태는 `유지 / 해지 / 신규추가` 3종을 모두 유지하되, **결론 조합의 사용 카드는 최대 2장 · 신규 발급은 최대 1장**으로 제한한다.

**근거:** 경쟁사 PDF p11이 CardFit 1차 MVP로 *"보유 카드 및 신규 카드 1장 추가 시나리오"* · *"최대 1-2장 조합"*을 제안했다. 다만 *"최대 1-2장"*은 **조합 크기 제한**이지 해지 금지가 아니다. 해지를 빼면 `FR-008`·`AC-003`(경계 고지)이 트리거되지 않아 요구사항이 사실상 사재기되고, "카드를 줄이는 것"이라는 결론 자체가 사라진다 — 강민재형(자녀 독립·지출 감소)에게는 그게 정답이다. CJM에서 이서연은 *"신규카드까지 만들 필요는 있나"*를 경계하고 정하늘은 *"신규카드 위주 추천이면 바로 이탈"*하므로 신규 1장 상한이 이탈 방지 장치이기도 하다. 기각 문서 `G-01`·`G-05`(불필요한 신규카드 방지 · 카드 수 통제)와도 일치한다.

**문서 간 값 불일치 해소:** `SRS.md` FR-003에는 조합 크기 제한이 없었고 PDF는 최대 1-2장이었다 → 최대 2장으로 확정.

**applied:**
- 설계문서: `docs/SRS.md` FR-003 Requirement·Rule + 6-1절 Constraint 기본값 · `docs/PRD.md` 5절 Must 행 · `docs/ux/README.md` 1-1절 조합 규칙 문단
- 하네스: `CLAUDE.md` — "사용 카드 최대 2장, 신규 최대 1장, 해지는 후보에 남긴다"
- 원장: 이 파일

### T7 — 미반영 항목 노출 방식 · RESOLVED

**decision:** 근거 패널 안 정적 표기 + **금액 영향 병기**. 재계산 토글은 두지 않는다.

**사용자 선택** — 권장안은 "정적 표기만"이었으나 금액 영향까지 표시하는 안이 선택됐다. 정보량이 늘어나는 대신 `G-02`(총혜택 과장 방지) 위반 위험이 생기므로, **금액의 출처를 Mock 규칙에 고정하는 가드 3종**을 함께 확정한다:

1. 값을 추정하지 않는다 — `BenefitRule.unmodeled_bound`에 **선언된 상한을 읽어** 합산한다
2. **"최대 ±n원"** 상한 형태로만 쓴다. 기대값·평균으로 쓰지 않는다
3. **결론 차액(`AC-006`)에 합산하지 않는다.** 별도 블록에만 둔다

**토글을 뺀 근거:** 경쟁사는 이벤트 포함/제외 토글로 순위를 재정렬한다(PDF p5, 857,000원 → 1,811원). 강력하지만 시나리오 3개 × 토글로 사전 계산량이 배가되고 `AC-005`(탭 전환 시 재계산 0건)와 정면 충돌한다. `AC-002`가 요구하는 것은 6항목 표기지 재계산이 아니다.

**형식이 차별점인 이유:** 경쟁사도 정확도 제약을 이미 공개한다(PDF p8 — 미연결 카드·실적 제외 항목·부분 거래 내역). `E-05`의 *"결과 금액만 공개"*가 완전히 맞지는 않다. 차별점은 공개 여부가 아니라 **결과 1건마다 근거가 따라붙는 인라인 형식**이다 — 경쟁사는 약관형 별도 화면(PDF p7-8)이다.

**applied:**
- 설계문서: `docs/SRS.md` FR-005 Rule에 가드 3종 · 6-1절 `BenefitRule.unmodeled_bound` 필드 신설 · 8절 AC-002 보강 · `docs/ux/README.md` **1-2절 신설**(근거 패널 스케치 + 규칙 표)
- 하네스: `CLAUDE.md` — "미반영 항목 금액은 추정하지 않고 결론 차액에 합산하지 않는다"
- 원장: 이 파일

### T8 — Mock 진입 · RESOLVED · **T1·T4 개정**

**decision:** 시작 화면 1개를 둔다. **라우트가 3개에서 4개로 늘어난다** — `시작 → 진단 → 입력 → 결과` + 수정 루프 1개.

**사용자 선택** — 권장안은 "동의 화면 없음 + 진단 화면에 Mock 배지"였으나 시작 화면을 두는 안이 선택됐다. 경쟁사도 같은 자리에 동의 화면을 둔다(PDF p4).

**함께 확정한 가드:** **마이데이터 동의를 받는 것처럼 그리지 않는다.** `D-001`로 연동이 없어 동의할 대상이 실제로 없고, 없는 절차를 금융 서비스 화면으로 그리면 오해를 만든다. 화면은 *"예시 데이터로 동작합니다"* 고지 + 시작 버튼만 두고, *"동의하고 계산 받기"* 류 문구와 약관·개인정보 체크박스는 만들지 않는다.

**개정된 선행 결정:**
- `T1` — 3라우트 → **4라우트**
- `T4` — 라우트 0(시작) 추가. `UI-001~008` 매핑은 변동 없음(시작 화면에 대응 UI 없음)

**applied:**
- 설계문서: `docs/ux/README.md` 라우트 다이어그램·표 개정 + **0절 신설**(시작 화면 · 두는 것/두지 않는 것 표) · `docs/SRS.md` 4절 라우트 표·수 개정 + 6-1절 User 엔터티 행 · `docs/SCOPE.md` 3절 흐름에 `[0] 시작` 추가
- 하네스: `CLAUDE.md` — 라우트 수 3→4 개정, "시작 화면은 동의를 받는 것처럼 그리지 않는다" 추가
- 원장: 이 파일

### T16 — D-002 Net Benefit 임계값 · RESOLVED · **프로젝트 최대 블로커 해소**

**decision:** **이중 조건** — `Net Benefit ≥ 50,000원` **AND** `Net Benefit ≥ Gross Benefit × 15%` (연 단위). 둘 중 하나라도 미달이면 "현재 조합 유지". **실측이 아니라 팀 합의 상수 🟡**이며 북극성 40%와 같은 처리다.

**근거:** 절대값만 쓰면 Gross 90만원에서 6.7% 개선에 카드 변경을 권하게 되고, 상대값만 쓰면 연 3천원 차이로 신규 발급을 권해 `G-01`(불필요한 신규카드 방지)과 충돌한다. 이중 조건이 양쪽 구멍을 서로 막고, `FR-005` 근거 화면에서 *"연 5만원 미만이거나 전체 혜택의 15%에 못 미치면 바꿀 가치가 없다고 봅니다"*로 한 줄 설명이 된다.

**부수 효과:** `AC-006`(차액 원 단위)이 변경 케이스뿐 아니라 **유지 케이스에도 적용**된다 — AC 범위를 넓혔다.

### T22 — 결론 배너 카피 규칙 · RESOLVED

**decision:** **이득 표현으로 통일.** 변경 시 *"조합을 바꾸면 연 n원 더 받아요"*, 유지 시 *"지금은 바꾸지 않아도 돼요 / 바꾸면 연 n원 손해예요"*. **금지어** — `총혜택` · `최대혜택` · `놓쳤어요` · `손해보고 있어요`. 금지어 사전은 `FR-008` 경계 문구와 같은 파일에 외부화한다.

**근거:** `T7`에서 미반영 항목을 남겨두기로 했으므로 **계산이 완전하지 않다는 걸 이미 인정한 상태**다. 그 상태에서 *"놓쳤다"*고 단정하면 `G-02`(총혜택 과장 방지)와 충돌한다. `KSF③`의 손실 가시화는 *"바꾸면 연 7,000원 손해예요"*가 담당하며, 그건 **계산한 범위 안의 손익**이라 단정해도 된다 — 금지한 것은 계산 밖까지 단정하는 표현이다.

**해소한 문서 결함:** 배너 표현이 문서마다 흩어져 있었다 — `User_Flow.png` *"186,000원 더 유리해요"*, `SCOPE.md` *"지금은 바꾸지 않아도 돼요"*, `ux/README.md` *"연 132,000원 더 받습니다"*(T15 이전의 근거 없는 숫자). 문구와 숫자를 함께 정리했다.
