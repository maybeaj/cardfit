**요구사항은 `UI-001`~`UI-008` 8개에 `T35`의 `UI-009`·`UI-010` 2개를 더해 10개입니다.** `UI-004`(계산)는
화면이 아니라 Loading 상태이고([`SRS.md`](../SRS.md) 7절), `UI-007`(근거)·`UI-008`(확정+경계)은
`User_Flow.png` ③④와 맞춰 **독립 화면**입니다. `UI-009`·`UI-010`은 새 요구사항 `FR-009`에 연결됩니다 —
*"요구사항 없는 화면을 만들지 않는다"*는 규칙 때문에 UI만 늘리지 않고 FR을 함께 신설했습니다.

> **`T4`의 "근거를 별도 화면으로 빼지 않는다"를 왜 뒤집었나** — 그 우려는 *"약관처럼 읽히면 안 된다"*였습니다
> (경쟁사 PDF p7-8은 유의사항을 약관형 별도 화면으로 뺍니다). `User_Flow.png` ③은 약관형이 아니라
> **결과 1건에 붙는 6항목 + 미반영 항목**이고 결론 화면에서 직접 진입합니다. 우려에 해당하지 않아 분리를 허용합니다.
> **다만 근거 화면은 결론 화면에서만 진입할 수 있어야 합니다** — 독립 메뉴로 접근 가능해지면 그때 약관이 됩니다.

**유저플로우의 종착점은 "조합 확정 + 경계 고지"입니다** (`T25` — `T1`의 *"결정 + 경계 고지"*를 개정).
근거 화면의 CTA `이 조합 적용하기`가 확정 액션이고, 화면 6이 확정 결과를 보여줍니다.
북극성 지표가 **조합안 선택률**(*"조합안 저장·확정 사용자 ÷ 결과 열람 사용자"*, KB `08_Value_Proposition.md` 5-2절)이라
확정 액션이 화면에 없으면 지표가 측정 대상 자체를 갖지 못합니다.

**대행하지 않는다는 원칙은 그대로입니다.** 신규 발급 1장은 카드사 공식 페이지로 **이동**시키고(아웃링크),
해지는 **안내만** 합니다. 아웃링크는 대행이 아니라 이동이라 [`SCOPE.md`](../SCOPE.md) 6절의 제외 사유
(직권·대행 권한 없음)에 해당하지 않습니다 — 뱅크샐러드도 발급 연계까지 갑니다(`01_Porters` 5절).
해지 마찰 민원 근거(`02_가치사슬` 1-5절)는 해지를 안내로 남기는 쪽으로 그대로 지켜집니다.

### 0. 뱅크샐러드 변환 규칙 — 앞단 2화면 + 대조군 · `T11` · `T35`

`BankSalad_Home.jpeg`(홈)·`BankSalad_Home_1.jpeg`(카드 탐색)을 앞단 2화면의 원본으로 씁니다.
**레이아웃과 비주얼 언어만 승계하고, 숫자는 전부 관찰된 사실로 바꿉니다.**

`BankSalad_Home_2.jpeg`(카드 순위)는 `[2-A]` 대조군의 원본입니다 — **이 화면만 금액을 승계하되**
과거 기준임을 화면이 밝히는 조건이 붙습니다. 변환 규칙은 [`0-2`](#0-2-과거-기준-결과-화면--banksalad_home_2jpeg-변환--t35).

| 승계하는 것 | 버리는 것 |

**탭을 그리지 않습니다** (`T14`). `T1`이 *"새 진입점·탭·분기를 추가하지 않는다"*이므로 탭을 그리면 동작하지 않는
가짜 요소가 생기고, 시연에서 누르는 순간 들통납니다. `User_Flow.png` 4화면 어디에도 탭이 없고 하단은
전부 **고정 CTA 버튼**입니다 — 선형 흐름에 그게 맞습니다.

**금액 자리에 사실을 넣습니다.** *"최근 6개월 1,240만원 쓰셨어요"* · *"실적 구간 미달 2장"* 처럼
큰 숫자 자리를 관찰값으로 채우면 화면 임팩트는 유지되면서 `T5`·`G2`·`AC-001`이 전부 살아남습니다.

> **왜 숫자를 못 가져오는가** — 뱅크샐러드 두 화면은 내용의 거의 전부가 **미래 입력 없이 산출한 금액 결론**입니다.
> 그대로 옮기면 앱이 시작하자마자 `G2`(*"미래 입력 없이 산출된 결과는 결과로 취급하지 않는다"*)를 깨뜨리고,
> 차별점이 *"과거 기준 추천을 하지 않는다"*인데 첫 화면이 과거 기준 금액이면 발표에서 바로 반박당합니다.

### 0-1. 홈 화면 — `T8`

경쟁사는 동의 화면이 흐름의 한 단계입니다(경쟁사 PDF p4 — *"내 소비 습관을 분석해서 더 잘 맞는 카드를 추천해드릴게요"* → `[동의하고 추천 받기]`).

**계산 기간은 기준일로부터 12개월이고, 모든 결과 금액은 "연 n원"입니다.**

| --- | --- |

게이팅이 거의 항상 "유지"로 떨어지고, 변경 제안이 나오는 케이스를 만들기 어려워집니다.

#### "현재 조합 유지" 화면의 구성 — `T21`

**유지 결론의 설득력은 "안 바꿔도 된다"가 아니라 "바꾸면 오히려 손해다"에서 나옵니다.**
게이팅을 통과하지 못한 최선 후보를 **검토했던 대안**으로 그대로 보여주고, 그 손익을 원 단위로 밝힙니다.

```

┌───────────────────────────────┐
│ ✓ 지금은 바꾸지 않아도 돼요       │  결론 배너 (--banner)
│   바꾸면 연 7,000원 손해        │  ← AC-006을 유지 케이스에도 적용
├───────────────────────────────┤
│ 지금처럼 쓰시면 돼요             │  배분표 — 현재 조합 기준
│  A카드  식비·교통      62만원   │
│  B카드  여행·쇼핑     120만원   │
├───────────────────────────────┤
│ 검토했던 대안                   │  게이팅 미통과 후보
│  C카드 신규   혜택   +31,000   │
│              연회비  −38,000   │
│              순      −7,000    │
└───────────────────────────────┘
```

**추가 계산이 필요 없습니다** — 게이팅 판정에 이미 최선 후보의 `gross_benefit`·`switch_cost`·`net_benefit`을
계산해 뒀으므로(`PlanCandidate`), 숫자를 반대 방향으로 보여주기만 하면 됩니다.

**이게 `AC-004`의 급소입니다** — *"바꿀 가치가 없다"*는 결론이 *"볼 것이 없다"*로 읽히면, 경쟁자가 못 하는
차별점이 오히려 빈 화면으로 보입니다. 강민재 프로필이 기본 탭에서 바로 이 화면이라 시연 비중도 큽니다.

**"유지" 결론일 때도 배분표를 비우지 않습니다.** 현재 조합 기준 배분표를 그대로 보여줍니다 —
바꿀 필요가 없다는 결론이 "볼 것이 없다"는 뜻이 되면 AC-004가 실패 화면으로 읽힙니다.

#### 결론 배너의 카피 규칙 — `T26` (`T22` 흡수)

`AC-006`은 차액의 기준선을 *"유지 시 예상혜택과 추천 조합 예상혜택의 차액"*으로 이미 정의해 뒀는데,
화면 문구가 그 기준을 말하지 않았습니다. **본문은 손실로 말하고, 캡션이 기준을 밝힙니다.**

| 결론 | 본문 (32px / 700) | 캡션 (13px / `--muted`) |
| --- | --- | --- |
| **변경 제안** | *"지금 조합 그대로면 <br>연 **186,000원**을 덜 받습니다"* | *"현재 조합 3장을 그대로 쓸 때와 비교 · 예상대로 탭 기준"* |
| **현재 조합 유지** | *"지금은 바꾸지 않아도 돼요"*<br>*"바꾸면 연 **7,000원** 손해예요"* (`T21`) | *"현재 조합 기준 · 예상대로 탭 기준"* |

**왜 손실로 말하는가** — `03_KSF` 3절이 *"놓치는 혜택을 손실로 보여주는 것"*을 차별화 KSF 1순위로 지목했고,
`01_Porters` 4절은 *"아무것도 안 하기"*를 가장 강력한 대체재로 판정하면서 그 상쇄 수단으로 같은 것을 지목했습니다.
이득 프레이밍(*"더 받습니다"*)은 안전하지만 그 차별화 축을 스스로 버립니다.

**가드 5종**

1. **차액은 `AC-006`의 값 그대로다** — 미반영 항목(`T7`)을 합산하지 않는다. 합산은 `G-02` 위반이다.
2. ***"총혜택"* 표현을 쓰지 않는다** (`G-02`) — 계산하지 않은 혜택(정책환급·프로모션)이 있기 때문이다.
3. **캡션의 탭 이름은 현재 선택된 시나리오 탭과 항상 일치한다** — 탭을 바꾸면 캡션도 바뀐다(`AC-005`의 사전 계산값에서 읽는다).
4. **손실의 방향은 결론마다 반대다.** 변경 제안은 *"그대로 두면 덜 받는다"*, 유지는 *"바꾸면 손해다"*(`T21`)이다.
   **유지 결론에 "그대로면 덜 받는다"를 쓰지 않는다** — 바꿀 가치가 없다고 판정해 놓고 변경을 부추기면
   `G3`(불필요한 전환 유도 금지)를 화면이 스스로 깬다. 반대로 변경 제안에 *"바꾸면 손해"*를 쓰지 않는다.
5. **과거형 손실 표현을 쓰지 않는다** — *"놓쳤어요"* · *"손해보고 있어요"*처럼 **이미 발생한 손실**을 단정하는 문형은
   과거 기준 계산을 암시해 `T5`·`G2`와 충돌한다. 시제는 **앞으로**여야 한다(*"덜 받습니다"* · *"손해예요"*).
   금지어 `총혜택` · `최대혜택` · `놓쳤어요` · `손해보고 있어요`는 `FR-008` 경계 문구와 **같은 파일에 외부화**한다 — 금지어 스캔 대상이다.

**캡션의 "3장"은 하드코딩하지 않습니다** — 현재 보유 카드 수에서 읽습니다. 프로필 ② 강민재는 장수가 다릅니다.

### 1-3. 근거 패널과 미반영 항목 — `T7`

근거는 **별도 화면이 아니라 결과 안의 펼침 패널**입니다(`T4`). 경쟁사는 유의사항을 별도 화면으로 빼서
약관처럼 읽히는 구조인데(경쟁사 PDF p7-8), **결과 1건마다 근거가 따라붙는 것**이 CardFit의 차별점입니다.

```
[5] 근거 화면
┌───────────────────────────────┐
│ 계산 근거                       │
│  ① 실적구간   30~50만원          │
│  ② 혜택한도   월 2만원            │
│  ③ 연회비     15,000원           │
│  ④ 제외조건   교통·세금           │
│  ⑤ 기준일     2026-08-31         │
├───────────────────────────────┤
│  ⑥ 이 계산에 포함되지 않은 항목    │
│     · 정부·지자체 정책환급         │
│     · 가맹점 프로모션             │
│     넣으면 최대 ±48,000원         │  ← 상한만, 결론 차액에 미합산
│     달라질 수 있습니다 🟡          │
└───────────────────────────────┘
```

**미반영 항목의 금액을 표시하되, 만들어내지 않습니다.** 값은 `BenefitRule`(Mock)의 `unmodeled_bound`에
**선언된 상한을 읽어** 합산합니다. 지켜야 할 3가지:

| 규칙 | 이유 |
| --- | --- |
| 값을 추정하지 않는다 — Mock에 선언된 상한만 읽는다 | 근거 없는 숫자를 만들면 `G4`(검증 가능성) 자체가 무너집니다 |
| **"최대 ±n원"** 상한 형태로만 쓴다 | 기대값으로 쓰면 사용자가 받을 것처럼 읽힙니다 |
| **결론 차액(`AC-006`)에 합산하지 않는다** | 합산하면 `G-02`(총혜택 과장 방지) 위반입니다 |

아웃링크가 0개이며 경계 고지는 그대로 노출됩니다 — `T2`에서 배분표를 비우지 않기로 한 것과 같은 이유입니다.
다만 북극성 지표는 *"유지 결론 제외"*로 정의돼 있으므로(KB `08_Value_Proposition.md` 5-2절)
**유지 결론의 화면 6 도달은 조합안 선택률에 집계하지 않습니다.**

> 확정 이벤트를 무엇으로 기록할지(엔터티·로깅 스펙)는 `T30`에서 정합니다. 이 절은 화면과 전이만 확정합니다.

### 4-3. 카드 실명과 "예시 수치" 고지 — `T18`

`User_Flow.png` ②③은 **실제 카드 실명**을 씁니다 — `신한 Deep Dream` · `우리 카드의정석 EVERY` · `삼성 taptap`.
**실명을 그대로 쓰되, 지어낸 수치임을 화면이 스스로 밝힙니다.**

| 위치 | 표기 |
| --- | --- |
| 조합 리스트의 카드 행 | `A카드 · 신한 Deep Dream` 옆에 **`예시 수치` 배지** |
| 근거 화면 `⑤ 기준일` 아래 | *"※ 수치는 예시이며 실제 약관과 다를 수 있습니다"* |
| 홈 화면 | *"예시 데이터로 동작합니다"* (`T8`에서 이미 확정) |

**왜 고지가 필요한가** — Mock의 실적 구간·혜택 한도·연회비를 실명 카드에 붙이면, 화면이
*"우리 카드의정석 EVERY는 100만원↑ 5.0%, 한도 월 2만원"*이라고 **단정**합니다. 실제와 다르면
특정 카드사에 대한 사실과 다른 표기가 됩니다. 경쟁사도 유의사항에 *"특정 세부 조건 미지 혜택이
반영되지 않을 수 있습니다"*를 답니다(경쟁사 PDF p8).

`User_Flow.png` ①이 이미 `A카드 · 신한 Deep Dream`처럼 **별칭 + 실명 병기** 구조라 배지 한 줄만 더하면 됩니다.

### 4-5. 과거 기준 결과(대조군) Mock — `T35`

`[2-A]`는 **계산하지 않습니다.** `PastSpend`(최근 6개월)만 읽어 만든 Mock 고정 리스트를 그대로 보여줍니다.
아래 수치는 **🟡 팀 합의 Mock**이며, `4-3`의 *"예시 수치"* 고지 규칙이 이 화면에도 그대로 적용됩니다.

**프로필 ① 이서연 — 과거 기준 순위**

| 순위 | 카드 | 과거 6개월 기준 예상 혜택 | 미래 기준 결론 |
| :---: | --- | ---: | --- |
| **1** | 삼성 taptap | 연 96,000 | **해지** 🗂 |
| 2 | 우리 카드의정석 EVERY | 연 71,000 | 유지 ✅ |
| 3 | 신한 Deep Dream | 연 42,000 | **신규 발급** 🆕 |

**이 표가 이 분기의 존재 이유입니다.** 같은 사용자·같은 보유카드인데 기준만 바꿨더니
**과거 기준 1위가 미래 기준에서는 정리 대상**이 되고, 과거 기준 꼴찌가 신규 발급 대상이 됩니다.
혼인 지출(가전·가구·예식)이 과거 6개월에는 없기 때문인데, 그게 바로 `01_Porters` 5절이
뱅크샐러드를 *"미래 소비 반영 ✗"*로 판정한 이유입니다.

**프로필 ② 강민재 — 과거 기준 순위**

| 순위 | 카드 | 과거 6개월 기준 예상 혜택 | 미래 기준 결론 |
| :---: | --- | ---: | --- |
| **1** | 신한 Deep Dream | 연 118,000 | — (발급 안 함) |
| 2 | 현재 보유 조합 | 연 87,000 | **유지** ✅ |

강민재는 자녀 독립으로 **지출이 줄어드는** 유형이라, 과거 기준으로는 *"바꾸는 게 낫다"*가 나오지만
미래 기준으로는 `AC-004` 게이팅에 걸려 **"현재 조합 유지"**가 정답입니다.
과거 기준 추천을 따랐다면 연회비만 더 내게 되는 케이스입니다.

> **순위 수치를 결론 화면의 금액과 섞지 않습니다.** `[2-A]`의 값은 과거 기준이고,
> `[4]` 결론 배너의 차액(`AC-006`)은 미래 기준입니다. 두 숫자를 같은 화면에 나란히 놓지 않습니다 —
> 기준이 다른 금액을 비교하는 것처럼 보이면 `G-02`(총혜택 과장 방지)에 걸립니다.

## 5. 상태 정의 — `T19`

| 상태 | 진입 조건 | 화면 | 구현 |
| --- | --- | --- | --- |
| **Loading** | 계산 실행 중 | `[4]` 결론 화면 — 3개 시나리오 사전 계산 진행 표시 | ☐ 필수 |
| **Empty** | `[3]` 입력에서 **모든 항목을 삭제했거나 금액이 전부 0** | `[3]` 입력 화면 안 — 안내 + `[과거 패턴으로 다시 채우기]`, `[다음]` 비활성 | ☐ 필수 |
| Error | Mock이라 네트워크·인증 오류가 없음 | **구현 안 함** — `D-001`로 API 장애·동의 만료가 해당 없음 | ☑ 해당 없음 |
| **임계 미달 → 현재 조합 유지** | `Net Benefit < 5만원` 또는 `< Gross×15%` | `[4]` 결론 화면 — **실패가 아니라 정상 결과** (`T21`) | ☐ 필수 |

### 5-1. Empty 상태의 발생 경로

`T3`(입력 화면은 제안값이 채워진 채로 열린다)과 `AC-001`(입력 0건이면 결과를 반환하지 않는다)이
서로를 막고 있었습니다 — **제안값이 항상 채워져 있으면 0건이 되는 경로가 없습니다.**

**해소:** 제안값은 그대로 채우되, **사용자가 모든 항목을 삭제하거나 금액을 전부 0으로 만든 상태**를 Empty로 정의합니다.

```
[3] 입력 — 전부 지운 뒤
┌─────────────────────────────┐
│ 앞으로의 지출을 적어주세요       │
│                              │
│   입력된 미래 지출이 아직 없어요  │
│   과거 기록만으로는 계산하지      │
│   않습니다                     │
│                              │
│ [과거 패턴으로 다시 채우기]        │
├─────────────────────────────┤
│ [다음]  ─ 비활성                │
└─────────────────────────────┘
```

**두 요구사항이 다 살아남습니다** — 첫 진입은 채워진 폼(`T3`), 다 지우면 Empty(`AC-001`).
`AC-007`이 이미 지출 **감소** 방향을 요구하므로 금액을 0으로 만드는 조작은 어차피 구현 대상이고,
그 조작의 극단이 Empty입니다. 시연에서도 *"다 지우면 어떻게 되나요"*로 자연스럽게 보여줄 수 있습니다.
