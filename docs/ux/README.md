> 상위 문서: `SCOPE.md` · `PRD.md` · `SRS.md`

## 1. 온보딩 및 단일 사용자 흐름

| 순서 | 화면 | 핵심 내용 | Primary CTA |
| ---: | --- | --- | --- |
| L | 온보딩 | `카드핏.png`, 서비스 한 줄 설명 | 카드조합 추천받기 |
| M | 마이데이터 이용 동의 | 이용 목적·범위, 예시 데이터 안내 | 마이데이터 이용 동의하기 |
| 0 | 현재 카드와 혜택 확인 | 최근 12개월 지출액·받은 혜택·보유 카드 상세 | 앞으로 쓸 돈 반영하기 |

결과에서 입력으로 돌아가 수정할 수 있다. 기준 선택, 카드 순위, 페르소나 선택 화면은 만들지 않는다.

## 2. 화면 계약

### 2-1. 온보딩과 마이데이터 이용 동의

- 온보딩은 모바일 우선으로 구성하고 화면 상단에서 약 1/3 지점에 `카드핏.png` 로고를 크게 배치한다. 로고 아래에는 서비스 가치 제안과 `카드조합 추천받기`를 둔다.
- 마이데이터 화면의 CTA는 `마이데이터 이용 동의하기`다.
- 화면 안에 `프로토타입에서는 예시 데이터로 카드 조합을 확인해볼 수 있어요`를 표시한다.
- 동의 CTA를 누르면 예시 데이터가 준비되고 `카드와 최근 소비 내역을 확인했어요`를 보여준다.
- 바텀시트에 프로토타입용 필수 동의 항목 체크박스와 전문 보기 자리를 표시한다. 체크 완료 전 CTA를 비활성화하지만 실제 인증·마이데이터 전송·법적 동의 수집은 하지 않는다. 12개월은 계산 대상 데이터 범위로만 표시하며, 동의 유효기간·파기기간으로 단정하지 않는다. 상세 기준은 [`../compliance/MYDATA_CONSENT_REVIEW.md`](../compliance/MYDATA_CONSENT_REVIEW.md)를 따른다.

### 2-1-1. 사용자 문구 원칙

- 오류·제한을 먼저 말하기보다 사용자가 확인하거나 시도할 행동을 안내한다.
- `오류가 발생했습니다` 대신 `입력 내용을 확인하고 다시 시도해보세요`처럼 쓴다.
- `결과가 없습니다` 대신 `앞으로 쓸 돈을 입력하면 카드 조합을 확인할 수 있어요`처럼 다음 단계를 안내한다.
- 내부 오류 코드, 테스트용 `0건`, 상태명은 사용자 화면에 직접 노출하지 않는다.

### 2-2. 현재 상태

현재 카드와 혜택을 보여줄 때 다음 정보를 표시한다.

- `최근 12개월 소비 기준`
- 최근 12개월 지출액: 사용자가 금액 숨김·보기 전환 가능
- 최근 12개월 받은 혜택: 결제내역과 카드 혜택 기준을 대조한 계산값임을 함께 표시
- 보유 카드를 누르면 카드별 주요 혜택 4개가 펼쳐짐
- 카드 목록은 프로토타입의 시각적 이해를 위해 공식 카드사 페이지에서 확인한 대표 상품 이미지 3개를 사용한다. 특정 상품이 국내 사용량 1위라고 단정하지 않으며, 이미지·혜택 문구는 실제 연동 전 최신 상품설명서와 약관으로 다시 검증한다.

이 단계에는 신규·유지·정리 판정과 CardFit 최종 조합을 표시하지 않는다.

### 2-3. 미래지출 입력

- 빈 폼으로 열지 않고 최근 소비 패턴으로 제안값을 채운다.
- `최근 소비 패턴으로 미리 채웠습니다. 달라질 항목만 수정해 주세요`를 표시한다.
- 항목은 카테고리, 추가 지출 금액, 지출 기간(`한 번에 / 3개월 / 6개월 / 12개월`)으로 구성한다. 증감 토글과 감소 입력은 제공하지 않는다.
- `지출 항목 추가`를 누르면 중간 선택창 없이 편집 가능한 새 항목 카드가 즉시 추가된다.
- 기간별 월 분배 계산값은 입력 화면에 표시하지 않고 결과 이후 근거 화면에서 공개한다.
- 모두 삭제하거나 전부 0원이면 CTA를 비활성화하고 `과거 패턴으로 다시 채우기`를 제공한다.
- 사용자가 확인한 계획을 계산 엔진이 임의로 늘리거나 줄이지 않는다.

### 2-4. 결과·배분

결과 화면은 단일 카드 조합안을 제시한다. 각 카드 행에는 다음 상태 중 하나만 표시한다.

- 화면 제목은 `카드 조합 결과`로 쓰고 `참고용` 문구는 노출하지 않는다.
- `적게 / 예상대로 / 많이` 탭은 각각 독립 계산된 카드 조합·손익·상태를 표시한다.
- 유지 결론의 사유와 예상 손익은 펼쳐보기 안에서 함께 제공한다.

| 상태 | 의미 | 화면 행동 |
| --- | --- | --- |
| **신규** | 현재 없지만 앞으로의 조합에 추가 | 공식 카드사 링크는 최대 1개 |
| **유지** | 현재 보유 중이며 앞으로도 사용 | `계속 사용` |
| **정리** | 현재 보유 중이지만 앞으로의 조합에서 제외 | 안내만 제공, 실행 버튼 없음 |

```text
┌───────────────────────────────┐
│ 지금 조합 그대로면              │
│ 연 186,000원을 덜 받습니다       │
│ 현재 조합과 비교                 │
├───────────────────────────────┤
│ 추천 카드 조합                   │
│ [유지] A카드  식비·쇼핑          │
│ [정리] B카드  앞으로 사용 안 함   │
│ [신규] C카드  가전·예식          │
├───────────────────────────────┤
│ 이렇게 나눠 쓰세요               │
│ A카드  식비·쇼핑      82만원     │
│ C카드  가전·예식     140만원     │
├───────────────────────────────┤
│ 왜 이런 결과인지 보기             │
└───────────────────────────────┘
```

임계 미달이면 모든 보유 카드는 `유지`이고 `신규·정리`는 0건이다. 이 경우에도 현재 조합 기준 결제 배분과 검토했던 최선 대안을 보여준다.

### 2-5. 결론 문구

| 결론 | 본문 | 캡션 |
| --- | --- | --- |
| 변경 | `지금 조합 그대로면 연 n원을 덜 받습니다` | `현재 조합과 비교 · 앞으로 12개월 계획 기준` |
| 유지 | `지금은 바꾸지 않아도 돼요 · 바꾸면 연 n원 손해예요` | `현재 조합과 비교 · 앞으로 12개월 계획 기준` |

금지어: `총혜택`, `최대혜택`, `놓쳤어요`, `손해보고 있어요`.

### 2-6. 근거와 확정

- 근거 6항목: 실적구간, 혜택한도, 연회비, 제외조건, 기준일, 미반영 항목.
- 출처가 있는 미반영 상한만 `최대 ±n원`으로 표시하고 결론 차액에는 더하지 않는다.
- 근거 화면에서만 `이 조합 적용하기`를 제공한다.
- 확정 화면은 조합 요약, 카드별 다음 행동, 실행 경계 3블록으로 구성한다.
- `정리` 카드에는 버튼을 두지 않고 `신청·해지는 카드사에서 직접 진행하셔야 합니다`를 표시한다.

## 4. Mock 데이터

Mock 데이터는 사용자 화면에서 선택시키지 않는다.

| Fixture | 목적 | 기대 결과 |
| --- | --- | --- |
| `change_case` | 변경 조합 검증 | 신규·유지·정리 상태가 모두 포함된 조합 |
| `maintain_case` | 과잉 추천 방지 검증 | 모든 보유 카드 유지, 신규·정리 0건 |

실명 카드를 사용할 경우 카드 행에 `예시 수치` 배지를 붙이고 근거 화면에 `수치는 예시이며 실제 약관과 다를 수 있습니다`를 표시한다.

## 5. 상태

| 상태 | 조건 | 처리 |
| --- | --- | --- |
| Loading | 계산 실행 중 | 미래지출 기준 조합 계산 진행 표시 |
| Empty | 모든 항목 삭제 또는 전부 0원 | 결과 생성 없이 입력 복구 안내 |
| 유지 결과 | Net Benefit 이중 임계 미달 | 정상 결과로 표시, 신규·정리 0건 |
| 근거 누락 | 필수 근거 6항목 미달 | 결과 노출 거부 |

Mock Seed와 Server Actions를 사용하므로 DB·서버 오류는 최소 오류 상태로 표시한다. 마이데이터·인증·카드사 API 오류 화면은 만들지 않는다.

## 6. 세션 상태

- 외부 카드사 페이지는 새 탭으로 연다.
- 복귀 시 직전 입력값과 확정 조합을 복원한다.
- 외부 링크 복귀용 화면 상태만 sessionStorage에 저장한다. Mock 데이터와 계산·확정 결과의 정본은 Server Actions를 통해 DB에 저장하며, 로그인 없는 새 세션·브라우저 간 계정 복원은 지원하지 않는다.

## 7. 화면별 완료 기준

- 카드별 상태값은 신규·유지·정리 외 `0건`이다.
- 유지 결론에서 신규·정리 표시는 각각 `0건`이다.
- 미래 계획 확인 전 CardFit 최종 결과는 `0건`이다.
- 정리 카드의 실행 버튼은 `0개`다.
- 배분 합계와 미래 계획 총액의 오차는 `≤1원`이다.
- 402×874와 1440×900에서 핵심 CTA와 결과가 가려지지 않는다.
