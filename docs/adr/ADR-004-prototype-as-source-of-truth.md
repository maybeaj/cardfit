# ADR-004 — 앱 화면의 정본은 v0.4 프로토타입 HTML이다

- 상태: 🟢 채택
- 날짜: 2026-09-03
- 대체: 없음. `ADR-001`(Mock First)·`ADR-003`(세션 상태)과 함께 읽는다.

## 배경

`docs/prototype/cardfit-prd-srs-v0.4.html`(이하 기준본)은 화면·문구·계산 규칙을 한 파일에
담은 검증용 프로토타입이다. PRD·SRS는 이미 기준본의 흐름으로 동기화되어 있다
(별도 확정 화면 폐지, `이 조합 좋아요`로 종료, 시나리오 3종 독립 계산).

반면 `/app` 구현은 기준본보다 앞선 세대의 화면을 가지고 있었다.

| 항목 | 기준본 | 구현(이전) |
| --- | --- | --- |
| 미래지출 입력 | 만원 단위 · 지출 기간 `한 번에/3/6/12개월` | 원 단위 · 증감 토글(`T10` 위반) |
| 사용 카드 상한 | 1~3장 | 1~2장 |
| 결과 화면 | 시나리오 탭이 조합·상태까지 교체 | 배수만 곱한 참고값 |
| 종료 | 결과 화면의 `이 조합 좋아요` | 별도 확정 화면(`/app/confirm`) |
| 데이터 | 실명 카드 3장(Mr.Life · taptap O · Deep Oil) | 마이데이터 CSV의 다른 카드 3장 |

또한 `/app` 레이아웃이 요청마다 Prisma로 Fixture를 읽고 있어, DB에 접근하지 못하면
데모 화면 전체가 오류 화면으로 대체됐다.

## 결정

**화면과 기준본이 다르면 기준본이 옳다.** `/app` 흐름을 기준본의 이식본으로 다시 쓴다.

1. **화면 데이터의 정본을 `src/fixtures/prototype.ts`로 옮긴다.**
   기준본은 시나리오별 카드 조합과 혜택 금액을 표로 고정해 둔 Mock이다. 규칙 엔진이
   재현할 수 없는 값이라 DB를 거치면 화면이 기준본과 달라진다.
2. **계산은 `src/domain/scenario.ts`가 순수 함수로 수행한다.**
   `projectedGross`·`buildScenario`는 기준본 JS의 식을 그대로 옮겼고 단위 테스트로 고정했다
   (`src/domain/scenario.test.ts`). 같은 입력이면 같은 결과다 (NFR-001).
3. **요청 경로에서 DB를 읽지 않는다.** `/app/*`는 전부 정적으로 프리렌더되며 런타임 외부
   의존이 없다. 발표 중 DB 장애가 데모를 멈추지 못한다.
4. **`/app/calculating`·`/app/confirm` 라우트를 폐지한다.** 기준본에 없는 화면이다.
   확정 액션은 결과 화면의 `이 조합 좋아요`가 대신한다 (FR-008 · UI-008).

## 유지한 것

- `src/server/**`(Prisma Repository·Server Actions)와 `prisma/**`는 **실연동 전환 지점으로 남긴다**
  (`ADR-001`). 지우면 마이데이터 연동 시 처음부터 다시 만들어야 한다.
- `src/domain/calc.ts`와 그 테스트, `src/fixtures/change-case.ts`·`maintain-case.ts`는
  규칙 엔진의 계약을 지키는 자산이라 그대로 둔다. 실연동에서 `scenario.ts`의
  고정 표를 이 엔진의 산출로 대체하는 것이 다음 단계다.

## 결과

- 좋음 — 화면·문구·금액이 기준본과 1:1로 대응한다. 배포가 외부 의존 없이 정적으로 끝난다.
- 좋음 — 계산이 순수 함수라 시나리오 3종의 값이 테스트로 고정된다.
- 나쁨 — 화면 데이터와 DB Seed가 두 벌로 갈라졌다. 실연동 시 `prototype.ts`의 표를
  규칙 엔진 산출로 바꿔야 하며, 그때까지 두 벌이 어긋날 수 있다.
- 나쁨 — `TECH_SPEC` 4절의 *"Mock의 정본은 DB"* 서술과 어긋난다. 이 ADR이 그 예외다.

## 되돌리는 조건

마이데이터를 실제로 연동하거나, 카드 규칙을 실제 약관으로 채워 규칙 엔진이 기준본의
시나리오 표를 재현할 수 있게 되면 `src/server/repository.ts`를 다시 요청 경로에 붙인다.
