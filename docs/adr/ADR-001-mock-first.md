# ADR-001 — v0.1은 Mock-first로 구현한다

- 상태: Accepted · **2026-09-01 개정** (`D-011`) — Mock의 소재지를 TypeScript Fixture에서 DB Seed로 옮김
- 결정일: 2026-09-01

## 맥락

카드 이용내역은 마이데이터 채널이 필요하고 카드 혜택 규칙은 공식 통합 API가 없다. 32시간 안에 실제 인가·제휴·개인정보 통제를 구현할 수 없다.

한편 실연동으로 넘어갈 때 무엇이 먼저 깨지는지 확인하려면, Mock이 코드 상수로 박혀 있는 것보다 **실제 데이터 접근 계층을 통과**하는 편이 낫다는 판단이 추가됐다 (`TEC-01~07`).

## 결정

보유카드·과거소비·혜택규칙은 명시적으로 표시한 Mock을 사용한다. 실제 인증·동의·연결 성공처럼 표현하지 않고 `예시 데이터 연결하기`로 표시한다.

**Mock은 Supabase Postgres에 Seed로 적재하고 서버 전용 Repository를 통해 읽는다.** `src/fixtures/*.ts`는 Seed의 입력 소스이자 정답셋으로 남기고 화면이 직접 import하지 않는다.

바뀌지 않은 것 — **마이데이터·카드사 API 실호출은 0건**이다. 바뀐 것은 Mock의 저장 위치뿐이다.

## 결과

사용자 흐름과 계산 안전장치를 검증할 수 있고, 실연동 전환 지점이 Repository 하나로 좁혀진다. 다만 실데이터 정확성, 가용성, API 비용, 실제 연결 성공률은 여전히 주장하지 않는다.

Seed·Migration이 시간 안에 나오지 않으면 Repository 뒤에서 Fixture를 직접 반환하는 경로로 되돌린다. 되돌리기 경로를 코드에 남긴다.
